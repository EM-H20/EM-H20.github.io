## 왜 만들었나

충청남도 예산군 은샘교회의 홈페이지입니다. 교인은 설교·주보·소식을 보고, 성경 통독 챌린지와 차량 탑승을 신청합니다. 고령 교인도 읽기 쉽게 글자와 버튼을 키웠습니다.

처음부터 **다른 교회도 `.env`만 채우면 쓰는 템플릿**으로 만들었습니다. 백엔드와 프론트엔드, 배포까지 혼자 했습니다.

## 기술적 결정

### 멀티테넌시 대신 교회마다 별도 인스턴스

- **상황**: 여러 교회가 같은 코드를 다시 쓰는 것이 목표였습니다.
- **선택지**: 테이블에 교회 id 컬럼을 두고 한 서버에서 나누거나, 교회마다 DB와 서버를 따로 두는 방법이 있었습니다.
- **판단**: 교회 id 컬럼을 두지 않고, 데이터 격리를 인프라에 맡겼습니다. 코드는 한 교회용으로만 쓰고, 교회마다 다른 값은 환경변수로 넣습니다.
- **결과**: 새 교회 배포는 코드 복사, `.env` 작성, 배포 세 단계입니다. 이 절차를 문서로 남겼습니다.

### 직분과 사이트 권한을 따로

- **상황**: 목사·장로·교사 같은 직분이 곧 사이트 권한은 아닙니다.
- **결정**: 직분과 권한을 별개로 두고, 인가는 `SERMON_WRITE` 같은 권한 단위로 검사합니다.
- **문제**: 처음에는 관리자가 다른 관리자를 임명하고 강등할 수 있었습니다.
- **결과**: 역할 부여·회수는 자기보다 낮은 역할에만 가능하게 바꿨습니다.

### 등록 폼: 모달 대신 전용 페이지

- **상황**: 공지·설교는 전용 페이지, 일정·갤러리·주보는 모달에서 등록했습니다. 모바일에서 태그 선택창이 모달 뒤에 깔리는 등 문제가 반복됐습니다.
- **선택지**: 모두 모달로 통일, 모바일에서만 모달을 전체 화면으로, 모두 전용 페이지로.
- **판단**: 모달 통일은 마크다운 에디터가 모달에 구겨집니다. 전체 화면은 비용이 가장 적지만 같은 계열의 문제가 남습니다. 그래서 전용 페이지로 통일하고, 삭제 확인 같은 작은 창만 모달로 남겼습니다.
- **결과**: 폼을 페이지로 옮기자 모바일 문제가 함께 사라졌습니다.

## 결과

- `www.eunsaem.com`으로 운영 중이고, PWA로 설치할 수 있습니다.
- 부서 사진을 WebP로 바꿔 46MB에서 5.5MB로 줄였습니다.
- 백엔드는 PR마다 실제 PostgreSQL로 전체 테스트를 돌리고, `deploy` 브랜치에 올리면 자동 배포됩니다.

## 배운 점

- **배포가 서버에 손으로 남긴 상태에 기대면, 그 상태가 사라지는 날 깨집니다.** 서버의 레지스트리 토큰이 지워져 배포가 실패했고, 이후 배포마다 일회용 토큰을 쓰게 바꿨습니다.
