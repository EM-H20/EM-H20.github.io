## 배경

충청남도 예산군에 있는 은샘교회(기독교 한국침례회)의 홈페이지입니다. 교인은 설교와 주보, 교회 소식, 사진을 보고, 성경 통독 챌린지에 참여하고, 교회 차량 탑승을 신청할 수 있습니다. 관리자는 콘텐츠와 회원, 역할·권한을 화면에서 직접 관리합니다.

처음부터 **한 교회만을 위한 코드가 아니라 다른 교회에도 다시 쓸 수 있는 템플릿**으로 설계했습니다. 교회 이름·도메인·시크릿 같은 차이는 전부 환경 변수로 주입하고, 새 교회를 추가할 때는 레포를 복사해 `.env`만 채우고 배포하면 되도록 "코드 수정 0"을 원칙으로 삼았습니다. 2026년 6월부터 백엔드와 프론트엔드를 혼자 만들었습니다.

## 맡은 역할

- **백엔드 설계·구현** — Spring Boot 4·Java 21·PostgreSQL·Redis·Flyway. 회원·JWT 인증, 역할·권한(RBAC), 설교·공지·일정·부서·갤러리·주보, 중앙 미디어 라이브러리, 문의, 성경 통독 챌린지, 차량 운행 신청 API
- **프론트엔드 구현** — Next.js 16 App Router·TypeScript·Tailwind CSS. 공개 페이지, 회원 전용 영역(설교·갤러리·통독·차량), 회원·역할·미디어·부서 등을 다루는 관리자 화면
- **디자인 시스템** — 디자인 토큰과 Button·Card 같은 시각 컴포넌트를 직접 구현하고, 고령 교인을 위한 글자·UI 크기 확대
- **배포·운영** — 백엔드는 GHCR 멀티아치 이미지와 SSH 배포(OCI VM, Docker Compose, Caddy HTTPS), 프론트엔드는 Vercel. GitHub Actions CI/CD, 구글·네이버 검색 등록 준비
- **문서화** — 전체 설계 명세, 기능별 설계·구현 계획 문서, 새 교회 배포·로컬 개발 가이드, 개발자와 AI 에이전트를 위한 진입 문서(`AGENTS.md`)

## 과정

**기능을 이슈 단위로 쪼개고, 설계 문서부터 썼습니다.** 백엔드는 빌드·공통 예외 처리·보안·파일 저장 같은 기반 4개와 직분·권한·회원·인증·태그·미디어·설교·공지·일정·부서·갤러리·주보·메인 통합 13개 도메인으로 나눴습니다. 기능마다 설계 문서, 구현 계획, 구현, CodeRabbit 코드리뷰 반영 순서로 PR을 만들었고, 6월 4일부터 7일까지 이 순서로 13개 도메인을 올렸습니다.

**프론트엔드는 토큰과 컴포넌트부터 시작했습니다.** 6월 10일 디자인 토큰과 공통 컴포넌트를 만든 뒤 메인, 설교, 공지, 일정, 주보, 로그인, 마이페이지, 갤러리, 관리자 화면 순으로 붙였습니다.

**연혁 페이지는 설계만 네 번 했습니다.** 처음 만든 연혁에 이어, 첫 시대를 풀스크린에서 축소하는 히어로를 넣었다가 다음 날 "모든 시대를 똑같이 다룬다"는 기준으로 걷어 내고 2단 타임라인으로 되돌렸습니다. 7월 초에는 참고 사이트를 직접 스크롤하며 관찰해 풀폭 그리드로 다시 바꿨고, 이때 sticky 사이드 영역과 스크롤 엔진을 지워 코드를 줄였습니다.

**실제 서버에 올리자 로컬에서는 안 보이던 문제가 나왔습니다.** 백엔드가 멈추면 홈 화면 전체가 에러 페이지로 바뀌어, 소식 영역만 실패하고 나머지는 정상으로 보이게 격리했습니다. 프로덕션의 상세 페이지가 전부 500을 낸 날은 마크다운 정화 라이브러리가 의존하는 jsdom이 이전 Node 런타임에서 동작하지 않는 것이 원인이어서 Vercel 런타임을 Node 22로 고정했습니다. 실제 설교 영상이 `youtube.com/live/` 주소라 임베드가 안 되던 것도 이때 고쳤습니다.

**기본 기능을 갖춘 뒤에도 기능을 이어서 붙였습니다.** 성경 66권 1,189장 구조를 상수로 두고 읽음 기록·소급·연속 기록을 계산하는 통독 챌린지, IP 기준 레이트리밋을 둔 문의하기, 현재 위치 좌표를 첨부하고 기사용 명단에서 지도로 여는 차량 탑승 신청, 홈 화면 설치(PWA), 검색엔진 최적화를 차례로 넣었습니다.

## 기술적 결정

### 멀티테넌시 대신 교회마다 별도 인스턴스

- **상황**: 여러 교회에 다시 쓸 수 있는 백엔드가 목표였습니다.
- **결정**: `church_id` 같은 테넌트 컬럼을 두지 않고, 교회마다 DB와 배포 인스턴스를 따로 두어 데이터 격리를 인프라에 맡겼습니다. 코드는 한 교회 기준으로 유지하고, 본문 속 이미지도 URL 대신 `media:{id}`로 저장해 도메인이 달라도 같은 본문이 동작하게 했습니다.
- **결과**: 새 교회 배포는 코드 복사, `.env` 작성, 배포 세 단계이고, 이 절차를 별도 문서로 남겼습니다.

### 직분과 권한을 분리한 RBAC

- **상황**: 교회에는 목사·장로·교사 같은 직분이 있지만, 직분이 곧 사이트 권한은 아닙니다.
- **결정**: 직분과 권한을 별개 축으로 두고, 관리자가 역할을 만들어 권한을 조합하게 했습니다. 인가는 항상 `SERMON_WRITE` 같은 권한 단위로 검사합니다.
- **문제**: 처음에는 같은 위계끼리 역할을 부여·회수할 수 있어, 관리자가 다른 관리자를 임명하고 강등할 수 있었습니다.
- **결과**: 역할 부여·회수는 자기보다 엄격히 낮은 역할만 가능하게 바꿨습니다. 이후 설교를 회원 전용으로 바꿀 때는 `SERMON_VIEW` 권한을 추가하는 마이그레이션과 경로 규칙 한 줄로 끝났습니다.

### 설교 회원 전용 전환: 서버 렌더링에서 클라이언트 조회로

- **상황**: 공개 페이지는 서버 컴포넌트와 ISR로, 회원 영역은 클라이언트에서 TanStack Query로 불러오는 경계를 두었고, 설교는 공개 영역이었습니다.
- **문제**: 설교를 갤러리처럼 교인 승인 후 열람으로 바꾸려 했지만, 로그인 토큰이 브라우저에만 있어 서버 컴포넌트에서 인증 요청을 보낼 수 없었습니다.
- **결정**: 설교를 회원 영역으로 옮기고, 갤러리용 게이트를 공용 `MemberGate`로 추출해 함께 썼습니다. 홈 화면의 최신 설교 카드 3개는 본문 없이 제목·설교자·날짜 같은 정보만 공개하고, 누르면 로그인이나 교인 승인으로 안내합니다.
- **결과**: 설교 상세가 검색엔진과 비로그인 공유 링크에서 사라지는 것은 의도된 결과로 받아들였습니다.

### 등록·수정 폼은 모달 대신 전용 페이지로

- **상황**: 공지·설교는 전용 페이지에서, 일정·갤러리·주보는 모달에서 등록·수정했습니다.
- **문제**: 모바일에서 태그 선택창이 모달 뒤에 깔리고, 모달이 화면에 꽉 붙어 깨져 보이는 문제가 반복됐습니다.
- **결정**: 모든 도메인을 전용 페이지 폼으로 통일하고, 삭제 확인처럼 작은 대화상자만 모달로 남겼습니다.
- **대안**: 모달로 통일하는 안은 마크다운 에디터가 모달에 구겨져 모바일에서 더 나빠지고, 모바일에서만 모달을 전체 화면으로 키우는 안은 비용은 가장 적지만 같은 계열의 문제가 남아 기각했습니다.

## 결과

- `www.eunsaem.com` 도메인으로 배포했습니다(프론트엔드 Vercel, 백엔드 OCI VM).
- 설교·공지·일정·부서·주보·갤러리·문의, 성경 통독 챌린지, 차량 탑승 신청, 관리자 기능, PWA 설치를 지원합니다.
- 사이트맵·RSS·구조화 데이터를 갖추고 네이버 사이트 소유 확인을 적용했습니다.
- 부서 사진을 WebP로 변환·리사이즈해 46MB에서 5.5MB로 줄였습니다.
- 백엔드는 PR마다 Testcontainers로 실제 PostgreSQL을 띄워 전체 테스트를 실행하고, `deploy` 브랜치에 올리면 이미지 빌드부터 헬스 체크까지 자동으로 배포됩니다.

## 배운 점

- **증상을 하나씩 막기보다 문제가 생기는 구조를 없애는 편이 낫습니다.** 모달 뒤에 깔리는 태그 선택창을 한 번 고친 뒤에도 모바일 문제가 이어졌고, 폼을 페이지로 옮기자 그 계열의 문제가 함께 사라졌습니다.
- **배포가 서버에 손으로 남겨 둔 상태에 기대면, 그 상태가 사라지는 날 깨집니다.** 서버에 남겨 둔 레지스트리 토큰이 삭제되자 배포가 실패했고, 이후에는 배포할 때마다 일회용 토큰으로 로그인하고 끝나면 로그아웃해 서버에 자격 증명을 남기지 않게 바꿨습니다.
