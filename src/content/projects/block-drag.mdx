## 배경

Block Drag는 매 턴 주어지는 블록 3개를 드래그 앤 드롭으로 그리드에 배치해 가로·세로 라인을 완성하는 모바일 퍼즐 게임입니다. 그리드는 6x6과 8x8 중에서 고를 수 있고, 보드에는 장애물이 무작위로 배치됩니다. 남은 블록을 하나도 놓을 수 없으면 게임이 끝나며, 보상형 광고를 보고 이어서 플레이할 수 있습니다.

개발부터 스토어 배포와 출시 후 업데이트까지 혼자 진행한 1인 개발 프로젝트입니다.

## 맡은 역할

- **게임 로직** — 블록 생성, 라인 클리어, 게임 오버 판정, 점수·콤보·티어·미션 규칙
- **UI와 연출** — 드래그 경로 표시, 라인 클리어·콤보 이펙트, 라이트/다크 테마, 튜토리얼
- **사운드와 진동** — 배경음악·효과음, 진동 피드백
- **수익화와 배포** — AdMob 배너·전면·보상형 광고, Google Play·App Store 빌드와 버전 업데이트

## 과정

**첫 주에 게임의 뼈대를 만들었습니다.** 2025년 4월 3일 첫 커밋 당일에 장애물을 넣고 다시하기 버그를 고쳤고, 이튿날 게임 오버를 판정하는 DFS 알고리즘을 고쳤습니다. 4월 8일에는 앱 번들 설정과 광고를 붙였습니다.

**재미는 숫자를 계속 고치며 찾았습니다.** 장애물 생성 확률, 점수 로직, 최대 콤보 제한, 블록 가중치를 여러 번 조정했습니다. 4월 말에는 MAX 콤보에 도달하면 긴 블록을 주는 Fantastic 콤보를 넣었고, 5월에는 MAX 콤보가 3사이클 뒤 끝나도록 바꾸고 곧바로 MAX 콤보가 되는 버그를 잡았습니다.

**넣었다 빼기도 했습니다.** 2.0.0(2025-05-10) 직후 8x8 그리드 선택을 잠시 주석 처리했고, 광고도 한 차례 제거했다가 사흘 뒤 다시 넣었습니다. 8x8은 지금 6x6과 함께 고를 수 있습니다.

**구조 개선은 두 번에 걸쳐 했습니다.** 2025년 7월 2.1.0에서 Supabase 로그인과 랭킹을 붙인 뒤, 9월에 게임 로직을 서비스 단위로 나누는 리팩토링을 먼저 했습니다. 그래도 약 50KB짜리 Provider 파일이 남아 있었고, 12월에 Clean Architecture 기준으로 프로젝트 전체를 다시 세웠습니다.

**다시 세운 뒤 기능을 하나씩 되살렸습니다.** 리빌드 과정에서 사운드 시스템을 걷어냈다가 2주 뒤 앱 생명주기와 연동되는 구조로 다시 넣었고, ShowcaseView 튜토리얼, 크리티컬 라인 미션, 게임 통계와 티어 시스템을 차례로 추가했습니다. 2026년 1월에는 점수 상수를 두 배로 올리고 언랭크 티어를 만들어 점수 체계를 다시 맞췄습니다.

## 기술적 결정

### Clean Architecture로 전체 리빌드

- **상황**: 게임 상태와 규칙이 Provider 기반의 큰 파일 하나(`game_provider.dart`, 약 50KB)에 몰려 있었습니다. 9월의 서비스 레이어 분리 이후에도 이 구조가 남아 있었습니다.
- **결정**: core·domain·data·presentation 4계층으로 나누고, 보드·점수·콤보 규칙을 domain 서비스(`BoardService`, `ScoreCalculator`, `ComboManager` 등)로 옮겼습니다. 상태는 Riverpod 코드 생성과 Freezed 불변 엔티티로 바꿔 `copyWith`로만 갱신하게 했습니다.
- **결과**: 레거시 Provider 코드를 지운 시점에 `flutter analyze` 결과가 59 errors에서 0 issues가 됐습니다. 이후 티어·미션 규칙도 같은 방식으로 domain 서비스에 추가했습니다.

### 로그인은 붙였다가 내려놓기

- **상황**: 2.1.0(2025-07)에서 Supabase 로그인, 랭킹, 점수 동기화를 붙였고, 12월 리빌드 때 Supabase 코드를 "추후 재구현 예정"으로 임시 제거했습니다. 12월 30일에 Supabase 기반 Google OAuth 로그인을 다시 통합했습니다.
- **결정**: 2026년 1월 2일 Supabase 의존성을 제거하고, 로그인 버튼을 누르면 "준비중입니다" 메시지를 보여주도록 바꿨습니다.
- **결과**: 게임 상태와 최고 점수는 서버 없이 SharedPreferences로 기기에 저장하는 구조로 배포를 이어갔습니다.

### 업데이트 안내는 GitHub에 둔 appcast로

- **상황**: 버전 단위로 수정과 기능을 자주 배포했습니다.
- **결정**: upgrader 패키지와 별도 GitHub 저장소에 둔 appcast 파일로, 새 버전이 나오면 앱 안에서 업데이트를 알리도록 했습니다(2025-05 도입).
