## 배경

세종대학교 학생들은 진로에 맞는 과목을 고를 때 수강편람을 일일이 찾아보거나 선배에게 묻는 경우가 많았습니다. **완익세종**은 성적표 Excel 파일을 올리고 희망 진로와 관심 분야를 입력하면, Google Gemini가 현재 강점과 보완할 영역을 분석해 학기별 추천 과목, 기술 스택, 활동을 담은 학습 로드맵을 만들어 주는 서비스입니다.

제13회 세종대학교 SW-AI 해커톤에서 2025년 12월 23일 오후부터 24일 아침까지 팀으로 개발했습니다. 저는 Next.js 프론트엔드 저장소를 맡았고, 백엔드는 별도 저장소의 Spring Boot 서버였습니다.

## 맡은 역할

- **화면과 UI 컴포넌트** — 드래그 앤 드롭 성적표 업로드, 진로 입력, 역량 분석과 학기별 타임라인, 단계별 상세 모달, Framer Motion 애니메이션과 세종대 브랜드 컬러
- **Next.js API Routes** — xlsx 기반 성적표 파싱(과목, 학점, 성적, 이수구분, 평균 평점), Gemini 기반 로드맵 생성
- **AI 챗봇 '세박사'** — 과목명·교수명·강의 시간 검색과 학업 상담, Markdown 응답 렌더링, 최근 대화 5개 유지
- **백엔드 연동** — Spring Boot API와의 데이터 구조 불일치를 분석해 문서로 정리하고, 응답을 프론트엔드 타입으로 바꾸는 어댑터 구현

## 과정

**오후에 시작해 저녁 전에 첫 로드맵을 띄웠습니다.** 프로젝트를 만들고 PRD와 공용 컴포넌트를 정리한 뒤, 업로드부터 로드맵 생성까지 이어지는 첫 흐름을 2시간이 채 안 돼 완성했습니다. 저녁에는 챗봇과 Gemini 연동을 붙이고, 파일 업로드와 챗봇 404 오류를 디버깅했습니다.

**밤 10시, 백엔드 문서와 프론트엔드 타입이 다르다는 것을 발견했습니다.** 백엔드는 학수번호·학점이 포함된 과목 객체를 반환하는데, 프론트엔드는 과목 이름과 유형만 쓰고 있었습니다. 필드명도 달라 그대로 붙이면 학점과 과목 코드가 화면에서 빠지는 상황이었습니다. 바로 고치기 전에 어떤 필드가 어떻게 다른지 분석 문서부터 썼습니다.

**새벽 3시에는 원인을 알 수 없는 400 에러를 만났습니다.** 백엔드는 상태 코드 외에 아무 정보도 주지 않았습니다. 추적해 보니 백엔드 호출이 실패하면 로컬 모드로 폴백하는데, 이때 주소는 여전히 백엔드를 가리키고 있어 프론트엔드 형식의 요청을 백엔드로 보내고 있었습니다.

**고치고 나니 이번에는 로드맵이 비어 있었습니다.** 백엔드 응답이 명세와 달리 프론트엔드 형식 필드명으로 오면서, 어댑터가 필수 필드를 찾지 못해 모든 과목을 걸러 내고 있었습니다. 시간이 없었기 때문에 두 형식을 모두 받는 임시 호환 처리를 넣고, 백엔드 쪽에서 고쳐야 할 항목은 따로 정리했습니다.

**발표 직전까지 고쳤습니다.** 아침에는 발표 대본을 정리하고, 서버·클라이언트 렌더링이 어긋나는 Hydration 오류(React #418)를 잡고, 프로덕션용으로 `console.log`를 정리한 뒤 마무리했습니다.

## 기술적 결정

### Mock·Local·Backend 3가지 운영 모드

- **상황**: 백엔드가 별도 저장소에서 동시에 개발되고 있었습니다.
- **결정**: API 호출 없이 UI를 개발하는 Mock 모드, Next.js API Routes에서 Gemini를 직접 호출하는 Local 모드, Spring Boot 백엔드를 쓰는 Backend 모드를 두고 환경 변수와 API URL로 자동 전환했습니다.
- **결과**: 백엔드가 준비되기 전에도 화면과 AI 흐름을 먼저 완성할 수 있었습니다.

### Backend 모드에서는 폴백하지 않기

- **상황**: 백엔드 호출이 실패하면 로컬 API로 넘어가도록 폴백을 두었습니다.
- **문제**: 폴백 경로가 여전히 백엔드 주소를 써서, 잘못된 형식의 요청이 백엔드로 가고 400 에러만 남았습니다. 진짜 실패 원인이 가려졌습니다.
- **대안**: 폴백 시 주소를 로컬로 바로잡는 방법, 폴백 경로에도 백엔드 어댑터를 적용하는 방법을 검토했습니다.
- **결정**: Backend 모드에서는 폴백을 없애고 백엔드 오류를 그대로 반환하게 했습니다. 로컬 API는 Backend 모드가 꺼져 있을 때만 쓰입니다.

### 백엔드 응답은 어댑터에서 프론트엔드 타입으로 변환

- **상황**: 백엔드 API 명세와 프론트엔드 데이터 구조가 달랐고, 실제 응답은 명세와도 달랐습니다.
- **결정**: 백엔드 응답을 프론트엔드 타입으로 바꾸는 어댑터 계층을 두고, 과목명·유형 필드는 두 형식을 모두 받되 명세와 다른 형식이 오면 경고 로그를 남기게 했습니다.
- **결과**: 백엔드 수정을 기다리지 않고 로드맵을 표시할 수 있었습니다. 호환 처리는 백엔드가 고쳐지면 제거할 임시 조치로 문서에 남겼습니다.

### 챗봇은 로컬 검색으로 폴백

- **상황**: 챗봇은 Gemini API에 의존했습니다.
- **결정**: Gemini 호출이 실패하면 세종대 과목 데이터를 대상으로 한 로컬 검색으로 자동 전환해 답변이 끊기지 않게 했습니다.

## 결과

- 제13회 세종대학교 SW-AI 해커톤 장려상
- 성적표 업로드 → 역량 분석 → 학기별 로드맵 → 챗봇 상담까지 이어지는 흐름을 해커톤 기간 안에 구현
- 백엔드-프론트엔드 API 불일치 분석, 400 에러 원인 분석, 응답 형식 불일치 분석을 문서로 남김

## 배운 점

- **명세 문서만으로는 계약이 되지 않습니다.** 문서와 코드, 실제 응답이 세 갈래로 달랐습니다. 불일치 분석 문서에서는 다음 단계로 명세 확정과 응답 스키마 검증(Zod 등)을 적어 두었습니다.
- **폴백은 실패를 숨길 수 있습니다.** 안전장치로 넣은 폴백이 원래의 실패를 가리고 원인 모를 400 에러만 남겼습니다. 분석 끝에 내린 결론은 Backend 모드에서 폴백을 없애는 것이었습니다.
