## 왜 만들었나

회의 내용을 노션에 정리해 둬도, 몇 주만 지나면 "**그때 어떻게 하자고 했었지?**"를 다시 묻게 됐습니다. 코드에는 "무엇을"은 남지만 "왜"는 남지 않아, AI 에이전트도 결정의 이유를 답하지 못합니다.

**Second Brain Template**은 회의·문서·이슈·결정을 프로젝트 안의 마크다운 볼트에 쌓고, 에이전트가 작업 전에 먼저 찾아보게 하는 템플릿입니다. 혼자 만들었고, 세 프로젝트에 적용해 쓰고 있습니다.

## 정말 도움이 되는지 재 봤습니다

경찰과도둑 프로젝트로 31문항 벤치마크를 만들었습니다. 같은 코드 저장소에 **A** 볼트+스킬+규칙 파일, **B** 볼트만, **C** 코드만, 세 조건을 비교했습니다. 경로 실존은 스크립트로, 정답 여부는 다른 모델이 채점했습니다.

- **정확도**: 볼트가 있으면 0.97, 코드만 있으면 0.71
- **"왜 이렇게 정했나" 질문**: 1.0 대 0.0. 코드만 있는 조건은 지어내지 않고 "기록이 없다"고 답했습니다.
- **없는 경로를 인용한 비율**: 8.3%에서 0.8%로
- **대조군**: 코드 위치 문항은 세 조건 모두 1.0. 그래서 위의 차이는 볼트에서 나왔다고 볼 수 있습니다.

예상과 다른 결과도 있었습니다. 31문항에서 스킬은 한 번도 자동 실행되지 않았습니다. 에이전트가 볼트를 찾은 건 규칙 파일 덕분이었습니다. 문항당 1회만 돌려, 한두 문항 차이는 우연일 수 있습니다.

- **상황**: 경찰과도둑 팀에 볼트를 들였지만, 볼트는 개발 도구로 여는 저장소였습니다. 비개발자 팀원은 열어 볼 방법이 없었고, 행사 현장에서는 개발자도 바로 확인하지 못했습니다.
- **한 일**: 팀 디스코드에서 물으면 볼트를 찾아 답하는 봇을 만들었습니다. 답에는 근거 노트 id를 붙이고, 못 찾으면 못 찾았다고 말합니다. 월·수·금 아침에는 창업 지원사업·공모전 공고를 모아 올립니다. 예전에 만든 길드 봇 [플래닝](/projects/planning)의 공지 자동 전송이 이 기능의 바탕입니다.
- **결과**: 만든 날 시험 사용에서 질문 17건 중 11건에 답하고 4건을 접수했습니다. 평균 응답은 9초, 월 $100 API 크레딧 안에서 돕니다.

## 기술적 결정

### 봇은 볼트를 고치지 않고 접수만

- **상황**: "이거 기록해 줘" 같은 요청이 디스코드로 들어옵니다.
- **판단**: 봇은 볼트를 읽기만 하고, 요청은 GitHub 이슈로 접수합니다. 반영은 담당자가 Claude Code에서 합니다. 원본 보존 같은 볼트 규칙은 사람이 확인한 경로로만 지키게 했습니다.
- **문제**: 처음 이슈에는 사용자 메시지만 들어가, 디스코드를 열어야 뜻을 알 수 있었습니다. 이슈 생성이 실패해도 봇은 저장했다고 안내했습니다.
- **결과**: 실패하면 원문을 서버에 남기고 담당자에게 알리게 했습니다. 이슈에는 봇이 정리한 "지식화할 내용"을 넣게 했고, 바뀐 형식의 첫 접수는 그대로 볼트 노트가 됐습니다.

## 배운 점

- **기대와 측정은 다릅니다.** 볼트의 효과는 숫자로 확인됐지만, 스킬이 알아서 실행된다는 전제는 틀렸습니다.
- **대조군이 있어야 차이를 믿을 수 있습니다.** 코드 위치 문항이 동률이라, 다른 차이를 볼트의 효과로 읽을 수 있었습니다.
