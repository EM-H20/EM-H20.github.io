## 배경

인스타그램 릴스나 유튜브에서 가 보고 싶은 장소를 발견해도, 저장하려면 장소 이름을 기억해 두었다가 지도 앱에서 다시 검색해야 했습니다. **트립게더**는 SNS 앱의 공유 버튼으로 링크를 보내면 서버가 콘텐츠를 분석해 장소 정보를 추출하고, 앱에 들어가면 분석된 장소가 정리되어 있는 AI 기반 여행 가이드 앱입니다.

팀 프로젝트였고, 저는 Flutter 앱을 맡았습니다. 콘텐츠 분석 서버는 별도로 개발됐고, iOS TestFlight·Play Store 배포 자동화는 팀원이 맡았습니다.

## 맡은 역할

- **공유 수신** — iOS Share Extension(Swift)과 Android Intent Filter·MethodChannel로 외부 앱의 공유를 받아 앱으로 전달
- **로그인과 토큰 관리** — Google 로그인, 로그인·토큰 재발급·로그아웃 API 연동, Dio 인터셉터 기반 JWT 자동 주입과 갱신
- **화면 구현** — 온보딩(약관·닉네임·생년월일·성별·관심사), 홈, SNS 콘텐츠 상세, 지도, 코스 마켓, 알림, 마이페이지·프로필 편집
- **지도** — Google Maps에 영업 상태를 표시하는 커스텀 마커와 장소 정보 바텀시트
- **푸시 알림과 다국어** — FCM 연동, 한국어·영어 지원
- **디자인 시스템** — 색상·텍스트 스타일·간격을 `core/theme/`에, 공용 위젯을 `shared/widgets/`에 모으고 하드코딩 값을 걷어 내는 작업

## 과정

**공유 기능부터 만들었습니다.** 저장소를 만든 다음 날 iOS 공유 수신을 완성하고 Android까지 활성화했습니다. 기획 문서(PRD)와 화면 구조는 그다음에 잡았습니다.

**화면을 빠르게 만든 뒤, 규칙을 세워 다시 정리했습니다.** 10월 초에는 홈·코스 마켓·국제화를 빠르게 붙였고, 중순부터는 화면마다 흩어진 색상과 크기 값을 테마 상수로 바꾸는 리팩터링을 이어 갔습니다. CodeRabbit 리뷰에서 지적된 메모리 누수와 하드코딩 문자열도 이 과정에서 고쳤습니다.

**디자인 피드백을 받을 때마다 화면을 다시 다듬었습니다.** 11월에 두 차례 디자인 변경 요청을 받아 온보딩, 홈, SNS 콘텐츠 카드, 바텀 내비게이션을 수정했습니다. 생년월일 입력처럼 한 화면을 하루 동안 여러 번 고쳐 쓴 경우도 있었습니다.

**공유 화면은 몇 번을 만들고 되돌렸습니다.** 공유 직후 "게시물을 추가했어요"라는 바텀 시트를 띄우고 싶었지만, 개발 환경에서 잘 보이던 화면이 TestFlight 빌드에서는 바로 사라지거나 인스타그램 공유 시트에 앱이 나타나지 않았습니다. 클래스 이름 지정, 활성화 규칙 완화를 단계별로 시험하는 진단 빌드까지 올려 본 뒤 알림 방식으로 되돌렸고, 다시 오버레이 형태로 시도했다가 최종적으로는 바텀 시트 없이 즉시 저장하고 닫는 구조로 정리했습니다.

**앱이 시작하자마자 멈추는 문제도 만났습니다.** iOS에서 라우터를 만드는 시점에 사용자 상태의 비동기 초기화가 끝나지 않아 앱이 멈췄습니다. 라우터 생성 전에 사용자 상태를 미리 초기화하고, Firebase → 로컬 알림 → FCM 순서로 초기화 순서를 정리해 해결했습니다.

**마지막 한 달은 백엔드 API를 붙이는 데 썼습니다.** 온보딩·관심사 API, 콘텐츠 API, 장소 저장, 지도 마커를 차례로 연결했습니다. 처음에는 Mock 데이터로 화면을 만들고, 환경 변수로 Mock과 실제 API를 전환하며 맞춰 갔습니다.

## 기술적 결정

### Share Extension은 저장만 하고, 처리는 앱이 맡기

- **상황**: iOS Share Extension은 Flutter 앱과 별도 프로세스로 실행되어 Flutter 코드에 접근할 수 없습니다.
- **문제**: Extension 안에 UI를 넣자 TestFlight 빌드에서 화면이 즉시 사라지는 등 동작이 불안정했습니다.
- **결정**: Extension은 공유된 URL을 App Group의 UserDefaults 큐(FIFO, 최대 100개)에 저장하고 바로 종료하게 했습니다. 앱이 다시 열리면 홈 화면이 큐를 읽어 서버로 보내고 목록을 새로고침합니다. Android는 Intent Filter와 MethodChannel로 같은 흐름에 합류시켰습니다.
- **결과**: 공유를 여러 번 연달아 해도 큐에 쌓였다가 앱에서 한 번에 처리됩니다. 토큰 오류가 나도 큐를 비워 무한 재시도를 막았습니다.

### 디자인 값은 한곳에서만 정의

- **상황**: 화면을 빠르게 만들다 보니 색상·텍스트 스타일·간격 값이 화면마다 하드코딩되어 UI가 조금씩 달랐습니다.
- **결정**: 색상·텍스트 스타일·간격을 `core/theme/`에, 공용 위젯을 `shared/widgets/`에 모으고, 하드코딩 값과 중복 위젯 생성을 금지 규칙으로 두었습니다.
- **결과**: `textTheme` 사용처 76곳을 공용 텍스트 스타일로 옮기고, 문자열 상수(AppStrings)를 없애 다국어 리소스로 통일했습니다.

### 토큰 재발급은 인터셉터 한곳에서

- **상황**: 화면에서 여러 API를 동시에 호출하다가 액세스 토큰이 만료되면, 요청마다 재발급을 시도할 수 있었습니다.
- **결정**: Dio 인터셉터에서 첫 요청만 재발급 API를 호출하고, 나머지 요청은 Completer로 재발급이 끝나기를 기다렸다가 새 토큰으로 재시도하게 했습니다. 블랙리스트 토큰이나 토큰 누락 응답은 자동 로그아웃으로 처리했습니다.

### 생년월일 입력을 칸 8개에서 입력창 1개로

- **상황**: 생년월일을 숫자 한 칸씩 8개 입력창으로 받았는데, 모바일 키보드에서 연속 백스페이스가 제대로 동작하지 않았습니다.
- **결정**: 입력창 하나에 숫자를 치면 `YYYY / MM / DD` 형식으로 자동 포맷팅되게 바꿨습니다. 중간 편집 시 커서 위치를 계산하는 로직도 만들었다가, 커서를 항상 끝으로 보내는 단순한 규칙으로 정리했습니다.
- **결과**: 입력창 8개·FocusNode 16개가 각각 1개로 줄었고, 커서 로직은 40줄에서 5줄이 됐습니다.
