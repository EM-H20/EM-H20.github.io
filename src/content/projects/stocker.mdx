## 왜 만들었나

주식을 처음 시작하면 무엇부터 배워야 할지 막막합니다. **Stocker**는 **초보 투자자가 이론 → O/X 퀴즈 → 오답 복습 순서로 배우는** 교육 앱입니다.

팀 돔황촤 코스피의 프로젝트로, 백엔드는 Node.js REST API입니다.

## 맡은 역할

Flutter 앱 프론트엔드 리드를 맡았습니다.

- **앱 구조** — 기능별 `data / domain / presentation` 구조와 라우팅
- **학습 화면** — 이론 학습, 퀴즈, 오답노트, 마이페이지
- **통합·마감** — 팀원 브랜치 통합, 실서버 연동, 릴리스 빌드 수정

## 기술적 결정

### API를 기다리는 대신 Mock으로 화면부터

- **상황**: 백엔드 API가 화면 개발 일정보다 늦게 나왔습니다. 그래도 일정상 화면과 UI/UX는 먼저 만들어야 했습니다.
- **판단**: 화면은 Repository만 보게 하고, 그 뒤에 Mock과 실제 API 구현을 나란히 뒀습니다.
- **결과**: 7월 말 Mock으로 화면을 만들고 9월에 실서버로 옮겼습니다. 전환은 실행 옵션 하나로 했습니다.

### Bloc·GetX 대신 Riverpod

- **상황**: 팀 가이드는 Provider였지만, BuildContext가 있어야 쓸 수 있고 등록 누락은 실행해야 드러났습니다.
- **선택지**: Bloc은 코드가 많아지고, GetX는 의존성이 드러나지 않아 디버깅이 어렵습니다.
- **판단**: 이 규모에는 Riverpod이 맞다고 봤고, Provider와 함께 두며 단계적으로 옮겼습니다.
- **결과**: 2025년 11월 Provider 의존성을 모두 걷어냈습니다.

### 퀴즈: 답마다 호출하는 대신 시작·종료 두 번

- **상황**: 답을 고를 때마다 API를 불러, 퀴즈 한 번에 "문항 수 + 2"번을 호출했습니다.
- **판단**: 듀오링고처럼 시작할 때 문제·정답·해설을 받아 두고, 답은 끝에 한 번에 냅니다.
- **결과**: 호출이 "문항 수 + 2"번에서 2번으로 줄었습니다.
